Bem-vindo à Metodologia 101 da Ciência de Dados, dos Requisitos aos Requisitos de Coleta de Dados! Se seu objetivo é fazer um jantar de espaguete, mas você não tem os ingredientes certos para fazer o prato, seu sucesso estará comprometido. Pense nessa seção da metodologia de ciência de dados como cozinhar com dados. Cada etapa é fundamental para preparar a refeição. Portanto, se o problema que precisa ser resolvido é a receita, por assim dizer, e os dados são um ingrediente, o cientista de dados precisa identificar: quais ingredientes são necessários, como obtê-los ou coletá-los, como entendê-los ou trabalhar com eles e como preparar os dados para atingir o resultado desejado. Com base na compreensão do problema em questão e, em seguida, usando a abordagem analítica selecionada, o cientista de dados está pronto para começar. Agora, vamos ver alguns exemplos dos requisitos de dados dentro da metodologia de ciência de dados. Antes de realizar as etapas de coleta e preparação de dados da metodologia, é vital definir os requisitos de dados para a classificação da árvore de decisão. Isso inclui identificar o conteúdo, os formatos e as fontes de dados necessários para a coleta inicial de dados. Então, agora, vamos dar uma olhada no estudo de caso relacionado à aplicação de “Requisitos de dados”. No estudo de caso, a primeira tarefa foi definir os requisitos de dados para a abordagem de classificação da árvore de decisão selecionada. Isso incluiu a seleção de uma coorte de pacientes adequada da base de membros das seguradoras de saúde. Para compilar as histórias clínicas completas, foram identificados três critérios para inclusão na coorte. Primeiro, um paciente precisava ser internado como paciente internado na área de atendimento do provedor , para ter acesso às informações necessárias. Em segundo lugar, eles se concentraram em pacientes com diagnóstico primário de insuficiência cardíaca congestiva durante um ano inteiro. Terceiro, um paciente deve ter sido inscrito continuamente por pelo menos seis meses, antes da internação primária por insuficiência cardíaca congestiva, para que o histórico médico completo possa ser compilado. Pacientes com insuficiência cardíaca congestiva que também haviam sido diagnosticados como portadores de outras condições médicas significativas foram excluídos da coorte porque essas condições causariam taxas de readmissão acima da média e, portanto, poderiam distorcer os resultados. Em seguida, o conteúdo, o formato e as representações dos dados necessários para a classificação da árvore de decisão foram definidos. Essa técnica de modelagem requer um registro por paciente, com colunas representando as variáveis no modelo. Para modelar o resultado da readmissão, era necessário que houvesse dados cobrindo todos os aspectos da história clínica do paciente. Esse conteúdo incluiria admissões, diagnósticos primários, secundários e terciários, procedimentos, prescrições e outros serviços prestados durante a hospitalização ou durante as visitas ao paciente/médico. Assim, um determinado paciente poderia ter milhares de registros, representando todos os seus atributos relacionados. Para chegar ao formato de um registro por paciente, os cientistas de dados colocaram os registros transacionais no nível do paciente, criando várias novas variáveis para representar essas informações. Esse era um trabalho para a fase de preparação de dados, portanto, é importante pensar no futuro e antecipar as etapas subsequentes. Isso encerra a seção Requisitos de dados deste curso.
